# Legacy Version-13 Import Boundary

## Approved Contract

The AutoHotkey version-13 main and archive files are one-time import sources. They are never
modified by the Python application. Patient UUIDs are generated by the Python application; legacy
six-digit MRNs remain optional and unique when present. Missing legacy species is represented as
`Unknown` and may be corrected later. Existing disposition and code-status values are preserved.

SOAP Markdown must be retained losslessly alongside any conservative structured mapping. Problems
remain hospital-day owned, with unresolved problems carried forward by later workflow services.

## Read-only validation

`icu_patient_tracker.persistence.legacy_v13` validates and decodes source files into typed,
in-memory transfer records. Its dry-run report contains only aggregate counts, file fingerprints,
format metadata, and validation diagnostics; it does not include patient names, MRNs, or clinical
text. It does not open the application database.

Run it with:

```powershell
python -m icu_patient_tracker.persistence.legacy_v13 `
  "C:\path\to\patient_tracker_data.txt" `
  "C:\path\to\patient_tracker_archive.txt"
```

The report also lists warning codes and proposed aggregate counts without exposing names, MRNs, or
clinical text. Review every warning before creating a staging database.

## Confirmed staging import

The production importer is deliberately separate from the normal application startup. It requires
an explicit empty target, a backup directory, and the exact `MAIN_SHA256:ARCHIVE_SHA256` token from
the reviewed dry run:

```powershell
python -m icu_patient_tracker.persistence.legacy_import `
  "C:\path\to\patient_tracker_data.txt" `
  "C:\path\to\patient_tracker_archive.txt" `
  ".\data\legacy-import-staging.sqlite3" `
  --backup-directory ".\backups\legacy-import" `
  --confirm "MAIN_SHA256:ARCHIVE_SHA256" `
  --timezone "America/New_York"
```

The command initializes and backs up the explicit target, imports all aggregates and its audit row
in one transaction, reconciles table totals, re-hashes both sources, and emits only a non-clinical
JSON result. It refuses a repeated source pair and refuses to merge into a database that already
contains patients.

Mapping is conservative:

- patient and day UUIDs are newly generated; hashed legacy identities provide provenance;
- legacy day keys retain their source identity in the audit map while their embedded ISO date is
  used for the hospital-day date;
- tasks retain legacy lineage, ordering, completion state, carry preference, priority, bucket, and
  supported reminder metadata;
- SOAP Markdown is copied losslessly and left structurally unparsed;
- the running legacy problem list is attached to the latest known hospital day;
- free-text devices are retained as `Other` devices;
- `ACTIVE_ORDER` is applied, while device-local presentation settings remain in the immutable
  sources and are not allowed to overwrite current Python preferences;
- global housekeeping is not assigned to an arbitrary patient. It remains in the immutable source
  and is reported for manual review until the domain has a true global-task owner.

Never point the first import at the configured application database. Import to staging, inspect a
deidentified sample, run the full suite and application restart test, then separately approve the
same fingerprint-bound command for the intended local database.
